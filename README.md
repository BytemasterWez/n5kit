# n5kit

Small shared run guards for Wesley's N5. Built and locally qualified under #0228; gate decisions and exact evidence are in evidence/FINAL-REVIEW.md and the board. Adoption by other projects is separate.

Use Python3.11+, Docker CLI and a user systemd manager. Job images must run as root and provide a chown executable for owned output repair; other images fail closed. `make check` runs preflight, Ruff, tests from a clean Git archive, guard mutations and a secret scan. Commit before checking; working-tree changes are refused. `make export` produces a clean source archive and SHA256 inventory in a fresh temporary directory. No install, publication or remote CI execution is implicit.

`make run SPEC=/absolute/job.json OUT=/absolute/evidence` runs a transient SERVICE. JSON requires an immutable local image ID and an argv array. Defaults:60seconds, container512MiB/64PIDs/1CPU; worker256MiB/64tasks; cleanup90seconds. Set `seconds` explicitly for a task, at most1800. Host floors are memory>16GiB, Docker disk>256GiB, Work disk>100GiB, load<2×cores. Explicit `floors` may tighten these minimums; they cannot drop another guard or weaken a floor without the explicitly authorized memory exception below. Resource caps on Docker are separate from systemd limits on the worker. The run must fit entirely before:52, including90seconds for cleanup, and start at:05 or later.

Each run owns a private evidence directory, a fresh token label, an internal network, one volume and one job container. No host ports, production mounts, live credentials, image pulls or app configuration are used. Output is mounted only under its fresh owned directory. `ExecStopPost` stops owned resources, uses an owned bounded helper to chown outputs without following symlinks, removes all label-owned resources and releases the reservation. Cleanup failure retains the reservation and records failure for an operator; do not delete it to hide a leak.

`make rehearse CASE=pass IMAGE=sha256:... OUT=/absolute/new/path` runs one real-host acceptance case. Cases:pass,term,kill,snapshot,booked,memory. Snapshot runs during the actual forbidden window and must create no run. Memory changes a rehearsal-only threshold after2seconds through the real host probe, never allocates host pressure. Kill destroys both the launcher process group and the service main process. These intentional faults are not product pass claims. No testcase reads personal content. Evidence includes START/END, timer inventory,5second samples, exit results and ownership receipts; job output is not copied into logs.

The API is trusted local tooling, not a sandbox for hostile same-UID callers or arbitrary untrusted images. Docker access is powerful. Supply only approved synthetic/public workloads; argv/config are recorded privately and must not contain credentials. Do not run Python with optimization flags that bypass project assertions (n5kit's own guards use explicit exceptions). Rehearsal injection must not appear in a normal trial's spec.

Project scaffolding is in `templates/project/`. The shared canonical copy is `/home/wez/Work/templates/project/`; configure a pinned library repository/revision for portable CI before enabling that workflow. FirstPass's receipted tooling is unchanged.

Admission also refuses active snapshot/backup/restore services or any such timer due before runtime+cleanup finishes. Timer records use LC_ALL=C/TZ=UTC; unknown deadlines refuse. Self-checks import only the extracted archive, not the working repository. This repository stays local; a GitHub publication needs Wesley's separate yes. Template action SHAs reuse the already pinned County workflow revisions.

Native jobs use `{"mode":"native","argv":["/absolute/python","/absolute/script.py"],"seconds":120}` with the same `make run` entry point. The script runs from its fresh output directory; there is no shell expansion, image or Docker resource. Native stdout/stderr/stdin are DEVNULL; write intended artifacts to the working directory. The service caps the job and all forks at256MiB/64tasks, and unit stop kills outstanding descendants. END's `orphans_killed` is the count observed at successful parent exit (null if interrupted before that observation). A successful parent may therefore leave children that are forcibly stopped; callers must inspect this count when detached work would be unexpected.

An already-running localhost model/service is outside this unit: MemoryMax does not cap Gemma/LM Studio memory. Host floors remain active and receipts state this scope. The native acceptance cases `native-pass` and `native-kill` use only synthetic Python forks, never model calls. Docker's pass/term/kill/snapshot/booked/memory acceptance on18563e5 is checked; the native extension has passed its synthetic pass/KILL acceptance; see the final review record.

Native cap amendment (lead21:14:32,10October): optional `memory` in bytes (default268435456), `pids` in tasks (default64), `seconds` (default60), all positive integers (booleans rejected), bounded at8GiB/256tasks/14400seconds. START/END record applied caps. These are maximum configurable values, not permission to bypass snapshot/calendar admission: with the current fixed hourly window, a4h job cannot be admitted. Docker worker limits and≤1800second rule are unchanged. Each native hard bound has a killed mutation test.

Offline isolation repair (lead21:17, checker21:18, lead21:20): real Docker/systemd/native subprocess backends require explicit N5KIT_REAL=1; default is a throwing fake. Unit-test processes and N5KIT_OFFLINE=1 refuse even with inherited opt-in. The check runner forces offline mode; an audit backstop denies non-test/non-Git subprocesses and writes to the canonical reservation/lock paths. Explicit temporary reservation fixtures remain allowed. Run/rehearse targets opt in; transient worker and ExecStopPost receive explicit N5KIT_REAL=1/N5KIT_OFFLINE=0. Direct CLI callers must opt in deliberately. No real gate execution until the checker reads this repair.

Native task evidence uses kernel pids.peak in `pids`, retains `pids_current`, and records the worker's own PID/thread baseline before launching the command (`worker-baseline.json`). Peak tasks and memory cover the whole unit, including the worker; do not subtract the baseline to pass a cap or margin.

A temporary memory-floor exception requires job fields `floors: {"memory": 10}` and `exception: {"authority": "Wesley approval reference", "card": "#0227", "expiry": "<timezone-aware ISO timestamp>"}`. This is an example schema, not authorization. Minimum permitted memory floor is 8 GiB; available memory must stay strictly above the requested floor. Authority/card must be nonblank strings; expiry must be strictly future and at most two hours ahead at every admission/guard probe. No block means the original 16 GiB minimum; a block alone keeps the default 16 GiB. Disk/load guards are unchanged. START and every END retain the block (null when absent); cleanup still runs after expiry. Trusted local approval metadata is not cryptographic authorization.

## Opt-in external mutation runner (#0434)

A repository with no `n5kit-check.json` gets exactly the behaviour above. A committed `n5kit-check.json` at the repo root, `{"mutation_runner": ["/abs/argv", "..."], "timeout_s": 60..7200, "reason": "text"}` (strict: no other keys, argv is a non-empty list of non-empty strings and is run without a shell), replaces only the per-mutant loop: `make check` still runs preflight, Ruff, secret and boundary scans and the baseline archive tests, still requires each `mutations.json` rule's `old` to occur exactly once, then runs the runner in the archived tree (same environment as the tests, plus the caller's) under the timeout. A non-zero exit or timeout fails the gate (`mutation_runner_failed`); a bad file fails with `mutation_runner_invalid`. The receipt records `mutations: "external"` and `mutation_runner` (argv, reason, rc, seconds, last 4 KB of output; the full output goes to stderr), never a kill count. The file is committed, so the opt-in is reviewable in the project's repo.

## Boundary enforcement (#0232)

New check/run adoption requires a reviewed `BOUNDARY.yaml` using strict JSON syntax (a YAML subset) and a nonempty `SCOPE-LOG.md`. The schema and rationale are in BOUNDARY-0232-SPEC.md; templates are examples to complete, not grants. `make check` scans the clean tree and complete files changed by HEAD, with every exclusion recorded in policy. It rejects literal forbidden paths, imports, database strings, hosts and fields. It is not a dynamic taint analysis. Missing or malformed policies fail closed. Each START/END retains the frozen policy and its hash, hosts and trusted sockets.

Native job and cleanup commands run inside bubblewrap. Only declared project write paths are writable persistent host mounts; source/inputs are read-only, other project roots absent, environment cleared, descriptors closed by Popen, and temporary /tmp,/run,/dev are private. The trusted reservation/guard controller stays outside. Docker gets a read-only root, read-only project/input mounts, writable owned output/scratch and private /tmp,/run. Its root-image contract needs DAC_OVERRIDE for uid1000-owned 0700 output; all other capabilities are dropped. This permits file-permission override inside visible mounts, not writing read-only mounts. Ownership cleanup is the pre-existing trusted helper.

An empty host list isolates networking. A nonempty list enables networking and static literal allowlist checking; it is NOT a runtime per-host firewall. Dynamic destinations, localhost and abstract Unix sockets remain reachable in native network mode. Explicit native `trusted_sockets` values docker/user-bus grant powerful host-control capabilities; Docker mode refuses these. The trusted same-UID caller can edit policy and is not the adversary addressed here. Boundaries do not grant source rights or permission for credentials, acquisition or release. Existing project pins remain unchanged, especially County C5 a8777a2/cc4c6e8.

`make rehearse CASE=sandbox IMAGE=unused-native OUT=<fresh path under write_paths>` is the one synthetic denial case: outside read/write denied, source write denied, allowed output succeeds and network namespace differs. It needs the normal real-run authorization/admission; unit tests never run bubblewrap, Docker or services.
